# Architecture

## Project Structure and Build System

The library is organized into multiple backends, each in its own source directory:

- `src-common/`: Backend-independent code (type classes, shuffle, fusible)
- `src/`: Backend-independent vector operations (Bundle, stream fusion)
- `src-no-simd/`: Scalar fallback (no SIMD instructions)
- `src-vl128/`: 128-bit vectors (x86 SSE, Arm NEON)
- `src-vl256/`: 256-bit vectors (x86 AVX2)
- `src-vl512/`: 512-bit vectors (x86 AVX-512)

Cabal flags (`no-simd`, `haswell`, `avx512`, `llvm`) control which backends
are built. The appropriate backend is selected based on the target platform
and available instruction sets.

## Key GHC Extensions

### TypeFamilies

- **Data families** define vector types with backend-specific representations:
  `data instance X4 Float = MkFloatX4 FloatX4#`
- **Type families** associate related types:
  `type family Mask a` maps element types to their mask representation,
  and `type family HalfVector x` maps vector types to their half-width counterparts.

### QuantifiedConstraints

The `SIMD` class uses quantified constraints to express that properties of
element types lift to vector types:

```haskell
class ( ...
      , forall a. SIMDNum a => Num (x a)
      , forall a. SIMDEq a => Equatable (x a)
      , ...
      ) => SIMD x
```

This means a single `SIMD x` constraint is sufficient to use all standard
type class operations on `x a`, as long as the element type `a` has the
appropriate `SIMD*` constraint.

## Hardware Vector Length vs Element-Count-Based API

GHC's SIMD primops are named after hardware vector lengths (e.g. `FloatX4#`
for 128-bit, `FloatX8#` for 256-bit). The library instead exposes an
**element-count-based** API (`X4`, `X8`, `X16`, `X32`, `X64`) that is
independent of the hardware vector width.

The same type `X8 Float` has different internal representations depending
on the backend:

- **vl128**: two `FloatX4#` fields (composed from 128-bit vectors)
- **vl256**: a single native `FloatX8#`

This decoupling allows user code to be written in terms of element counts
and ported across backends by simply switching the import.

## Supplementing Primitives Not Provided by GHC

As of GHC 9.14, GHC's SIMD primops cover basic arithmetic (`+`, `-`, `*`, `/`), FMA, and min/max,
but do not provide abs, sqrt, bitwise operations, comparisons, or select
(`abs`, `sqrt`, and certain bitops are added in GHC 10.0).
The library fills these gaps using two strategies:

### Relying on LLVM Optimization

Operations like `abs` and `sqrt` are written as scalar-per-element expansions:

```haskell
absFloatX4# u = case unpackFloatX4# u of
  (# u0, u1, u2, u3 #) -> packFloatX4# (# fabsFloat# u0, fabsFloat# u1, fabsFloat# u2, fabsFloat# u3 #)
{-# INLINE [0] absFloatX4# #-}
```

With `INLINE [0]`, these are inlined at the final simplifier phase and passed
to the LLVM backend, whose SLP vectorizer reassembles them into single SIMD
instructions.

### C FFI with Platform Intrinsics

Bitwise operations (complement, and, or, xor), shifts, select, and
comparisons are implemented as C functions using SIMD intrinsics directly
(`_mm_and_si128` / `vandq_s8` etc.) and called via `foreign import ccall`.
Platform-specific variants are provided for each ISA level (baseline / Haswell / AVX-512).

### Floating-Point min/max

Although GHC 9.12+ provides min/max primops for vectors, the library implements its
own floating-point min/max in C to ensure IEEE 754-2019 compliant NaN handling.

## Code Generation Scripts

Many source files are generated by scripts (indicated by a first-line comment
`-- This file was created by script/<name>.hs. Do not edit by hand!`):

- `script/Gen.hs`: Generates vector type modules (X2--X64) and their
  instances for all supported element types, across all backends.
- `script/GenVL.hs`: Generates public API modules (e.g.
  `Data.Simdy.Internal.VL128`) with summary classes (`SIMDElement`,
  `SIMDNum`, etc.), the `SIMD` class, shuffle wrappers, and rewrite rules.
- `script/GenPrim.hs`: Generates primop wrappers (`Prim.hs`) that provide
  operations not available as GHC primops.

## Type Class Hierarchy and DerivingVia

### F-Suffixed Classes

Core operations are defined in "F-suffixed" classes parameterized by the
vector type constructor:

- `NumF x a`, `FractionalF x a`, `FloatingF x a` (arithmetic)
- `EquatableF x a`, `OrderedF x a` (comparison)
- `BooleanF x a`, `BitShiftF x a` (bitwise)
- `MinMaxF x a`, `FusedMultiplyAddF x a`

### DerivingVia with WrappedMulti

The `WrappedMulti x a` newtype bridges F-suffixed classes to standard classes:

```haskell
deriving via WrappedMulti X4 a instance NumF X4 a => Num (X4 a)
```

### Summary Classes

Backend-specific modules define summary classes (e.g. `SIMDNum`) that bundle
the F-suffixed constraints for all vector widths, simplifying user-facing
type signatures.

## HalfVector and Horizontal Fold

The `HalfVector` type family and `SplitShortVector` class enable recursive
decomposition of vectors:

```haskell
type family HalfVector x    -- e.g. HalfVector X8 = X4
class SplitShortVector x a where
  splitShortVector :: x a -> (HalfVector x a, HalfVector x a)
```

`horizontalFold` uses this to reduce a vector to a scalar by recursively
splitting and combining halves:

```haskell
horizontalFold op v = case splitShortVector v of
  (low, high) -> horizontalFold op (op low high)
```

## Stream Fusion

The library uses stream fusion (similar to the `vector` library) for bulk
vector operations.

### Bundle

```haskell
data Bundle m x a = forall s. MkBundle
  { sMultiStep     :: s -> m (s, x a)   -- SIMD-width step
  , sStep          :: s -> m (s, a)     -- scalar step (remainder)
  , sInitialState  :: s
  , sSize          :: !Int
  }
```

The existential state `s` enables stateful iteration without exposing the
state type.

### Rewrite Rules and Phase Control

- `stream`/`unstream` rewrite rules eliminate intermediate allocations:
  `stream (new (unstreamAsNew s)) = s`
- `INLINE [1]` on public functions allows rules to fire before inlining.
- `INLINE [0]` on inner step functions ensures they are inlined at the
  final phase.

## Rewrite Rules

Beyond stream/unstream fusion, the library uses rewrite rules for:

- **`liftSIMD` specialization**: Common `liftSIMD coerce` patterns are
  rewritten to direct constructor calls (e.g. `liftSIMD coerce = mkSum @X4`).
- **FMA fusion** (via `Data.Simdy.Fusible`): The module defines
  its own `(+)`, `(-)`, and `(*)` operators (to be qualified-imported) with
  `INLINE [0]`, so that rewrite rules can match on them before they are
  inlined to the Prelude definitions. Patterns like `a F.* b F.+ c` and
  `a F.- b F.* c` are rewritten to `fusedMultiplyAdd` when FMA is
  enabled.

## Shuffle System

GHC's shuffle primops (e.g. `shuffleFloatX4#`) require their index arguments
to be **compile-time constants**. The library wraps this constraint using
a type class and a compiler plugin:

- **`ShuffleMany`**: A "magic" type class with no hand-written instances.
  Its method `shuffleMany# :: (Natural -> v) -> v` takes a source-vector
  selector and produces the shuffled result.
- **Compiler plugin** (`Data.Simdy.Shuffle.Plugin`): A `TcPlugin` that
  solves `ShuffleMany` constraints by reading type-level `[Natural]` indices
  and generating Core expressions that call the appropriate shuffle primop
  (GHC 9.12+) or fall back to `unpack`/`pack`.
- **`RequiredTypeArguments`** (GHC 9.10+) allows shuffle indices to be
  passed as type-level tuples with clean syntax.

## C FFI (cbits/)

The `cbits/` directory contains C implementations for operations that
benefit from direct use of SIMD intrinsics.

Operations implemented in C include: bitwise logic, shifts, select,
comparisons, floating-point min/max (IEEE 754-2019), and mask
pack/unpack.

## Platform-Specific Workarounds

- **Integer SIMD availability**: Integer vector primops are conditionally
  available depending on the GHC version and backend combination.
